Content-opportunity issues (blog, tutorial) filed during a review council live only in the issue tracker unless the change's tasks.md workflow follow-up references them alongside the gate-mandated docs issues. In opencode-reasoning-audit's audit-supervisor change, the curator-filed blog (jflowers/opencode-reasoning-audit#3) and tutorial (#4) issues verified as open, but tasks.md's follow-up bullet named only the two mandated documentation issues (in-repo #2 and unbound-force/website#321) — so the change-to-content linkage disappears when the change directory is archived. Pattern: whenever content-opportunity issues are filed for a change, add their references to the change's tasks.md workflow follow-up in the same edit, making opportunity issues as discoverable from the change artifact as gate-mandated ones.
