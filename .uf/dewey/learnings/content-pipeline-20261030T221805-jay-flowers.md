jflowers/opencode-supervisor maintains a per-minor-release blog cadence: each minor release has an open tracking blog issue (2.0→#7, 2.1.0→#12, 2.2.0→#16, 2.3.0→#21, 2.4.0→#25). A curator sweep for a new minor release should search for that release's blog issue by version number ('blog: ... 2.5.0'), not only by topic keywords, and should treat a release that adds new capability specs (like 2.5.0's supervisor-logging and auditor-config) as meeting the blog significance bar even when the release reads primarily as a fix.
